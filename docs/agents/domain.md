# Domain Docs

Engineering skills use a single domain context for this repository.

## Before exploring

- Read `CONTEXT.md` at the repository root when it exists.
- Read relevant architectural decisions under `docs/adr/` when they exist.
- If either location does not exist, proceed silently. Producer skills create them when decisions crystallize.

## Vocabulary

Use the terms defined in `CONTEXT.md` in proposals, tests, local issues, and architectural decisions. If a necessary concept is missing, treat that as a domain-language gap to resolve rather than introducing synonyms casually.

## ADR conflicts

If proposed work contradicts an existing ADR, identify the conflict explicitly instead of silently overriding the recorded decision.
